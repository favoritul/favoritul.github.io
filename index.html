Proyectos

El mismo sistema, dos ecosistemas.

Un sistema de facturación con arquitectura de microservicios, construido desde cero en Java y en .NET. No es el mismo código traducido: es el mismo problema resuelto dos veces, para entender qué decisiones son de arquitectura y cuáles son del framework.

Java

Sistema de Facturación

Java 25 · Spring Boot 4 · Spring Cloud Gateway

Tres microservicios con base de datos propia cada uno, detrás de un gateway reactivo. Autenticación con JWT de firma asimétrica, autorización por rol y por propiedad del recurso.

  • Firma RSA: solo el servicio de auth tiene la clave privada
  • Defensa en profundidad: el gateway valida y cada servicio vuelve a validar
  • Migraciones versionadas con Flyway y ddl-auto: validate
  • 22 tests en tres niveles, incluidos los slice tests de Spring
  • Docker multi-stage, contenedores sin root, solo el gateway expuesto
Spring Boot 4Spring SecuritySpring Data JPA HibernateFlywayJWT / RSA JUnit 5MockitoDockerMySQL

.NET

Sistema de Facturación

.NET 10 · ASP.NET Core · YARP

La misma arquitectura sobre el ecosistema .NET. Mismas reglas de negocio, mismas decisiones de seguridad, implementación idiomática de cada plataforma.

  • Entity Framework Core con Fluent API y migraciones versionadas
  • YARP como reverse proxy, con política de autorización por ruta
  • Result Pattern en lugar de excepciones para el control de flujo
  • 23 tests: unitarios, de controlador con Moq y de integración HTTP
  • Docker multi-stage: 356 MB frente a cerca de un giga sin optimizar
.NET 10ASP.NET CoreEF Core YARPJWT / RSABCrypt xUnitMoqDockerMySQL

Por qué dos veces. Construir el mismo dominio en ambos ecosistemas obliga a separar lo que es arquitectura de lo que es sintaxis. El snapshot del precio en una factura, el 404 en lugar del 403 al pedir un recurso ajeno, o el aislamiento de red del gateway son decisiones que valen igual en Java que en C#. Lo que cambia es cómo se escriben.
